# KYNG CUP — локальная проверка результатов игрока

Снимок локальной приёмки перед публикацией ветки `feat/player-results-stats`. На момент этой проверки новая миграция ещё не применялась к удалённой базе; фактический статус публикации определяется GitHub Actions и историей миграций Supabase.

## Реализовано

- История сыгранных матчей по турнирам: соперники, партнёр, этап, результат и счёт со стороны игрока.
- Статистика: сыграно, победы, поражения, доля побед, завершённые турниры, текущая/лучшая серия.
- Фильтр «Все / Tennis / Padel» для истории, статистики и достижений.
- Двенадцать пересчитываемых достижений с условиями, earned/locked-состоянием и прогрессом накопительных наград.
- Явная связь подтверждённой заявки с парой в админке, отключение связи, проверка записи перечитыванием, обновление связей при Refresh applications.
- Защита от устаревшего отображения другого аккаунта, поздних RPC-ответов и повторного submit во время write/read-back.
- Приватный серверный RPC истории, ограничения доступа и локальная PostgreSQL-регрессия.

## Ограничения и замечания

- Полный `tsc --noEmit --incremental false` возвращает exit 2: восемь диагностик типов Cloudflare/Deno в существующих `db/index.ts`, `worker/index.ts` и `supabase/functions/organizer-login/index.ts`. В изменённых файлах диагностик нет.
- npm audit сообщает 27 уязвимостей зависимостей, ровно столько же на HEAD: 1 low, 10 moderate, 16 high. Новых отмеченных пакетов нет; PGlite не отмечен. Обновления чужих зависимостей в эту работу не включены.
- PGlite-проверка не заменяет полный Supabase или проверку конкуренции на независимых соединениях.
- Локальная браузерная QA использовала явные fixtures, не настоящие профили; это не опубликованный пользовательский E2E.
- Матчи с обеими собственными сторонами исключены как неоднозначные. Технические проходы не считаются сыгранными. При неизвестном/одинаковом времени завершения матчей серии не начисляются.

## Продолжение

Сначала согласование локальной версии, применение проверенной миграции и публикация через штатный GitHub workflow. После этого — отдельно отложенный пользователем полный сценарий через опубликованный интерфейс. В рамках этой работы remote mutations, commit, push и deploy не выполнялись.

Правила и воспроизводимые команды: `docs/player-results.md`.
