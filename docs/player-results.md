# История, статистика и достижения игрока

## Источник данных

`get_my_match_history()` берёт идентификатор из Auth-сессии, а не из параметров браузера. Доступ разрешён подтверждённому, неанонимному и незаблокированному участнику. Источник принадлежности — `submitted_by` / `partner_user_id` подтверждённой заявки и явная связь заявки с парой в сетке. Поиск по имени или email не используется. Черновые турниры, контакты и заметки организаторов в ответ не входят.

Организатор выбирает пару в карточке подтверждённой заявки. Для смены пары требуется сначала отключить прежнюю связь. Одна пара не может одновременно принадлежать двум заявкам. Удаление заявки или пары каскадно удаляет связь. После записи интерфейс перечитывает точную связь; ошибка проверки не показывается как успех.

Если аккаунт связан с обеими сторонами одного матча, этот матч исключается из персонального ответа: произвольный выбор стороны по UUID не может определять победу или поражение. Остальные однозначные матчи собственных пар сохраняются.

## Правила подсчёта

- Матч учитывается только при `completed`, двух разных определённых парах, участии собственной пары и валидном счёте с соответствующим победителем.
- Технические проходы без соперника или счёта не учитываются. Scheduled/live остаются в API для определения выхода из группы, но не входят в сыгранную историю и W/L.
- Счёт всегда показан со стороны игрока; результаты групп, основного плей-офф и утешительной сетки различаются.
- Завершённый турнир — один distinct tournament ID со сыгранным матчем и статусом турнира `completed`.
- Фильтр «Все / Tennis / Padel» применяется к истории, статистике и достижениям.
- Серия вычисляется только при валидных и уникальных `completed_at` всех выбранных сыгранных матчей. При неоднозначной хронологии показывается «—» и пояснение, а награда за серию не выдаётся. Даты расписания и сортировка UUID не доказывают последовательность побед.
- Награды пересчитываются из результатов. Сброс или исправление счёта может убрать награду. Хранилища постоянных выданных наград нет.
- «Из группы» — сыгранный групповой матч и появление пары в основном плей-офф с `round > 0`. Играть плей-офф для этой награды не обязательно. Предварительный раунд и утешительная сетка не подходят.
- Четвертьфинал/полуфинал определяются расстоянием до максимального раунда соответствующей сетки и требуют сыгранного матча. Финал API требует максимальный раунд, `round > 0` и отсутствие следующего матча.
- «Чемпион» / «Второй шанс» требуют победы в сыгранном финале соответствующей сетки завершённого турнира.
- «Сыгранная пара» требует три завершённых турнира с одним и тем же связанным аккаунтом партнёра. Совпадающего имени недостаточно.

## Проверки локально

Node >= 22.13.0:

```sh
npm ci
npm test
npm run test:player-sql
npm run lint
npm run build:pages
git diff --check
```

`test:player-sql` использует PostgreSQL/PGlite в памяти. Схема-фикстура `tests/fixtures/player-history-schema.sql` содержит только структуру и Auth-хелперы, без данных участников и уведомлений. Runner дополнительно загружает настоящие функции проверки счёта и триггеры заявок из существующих миграций. Тест не подключается к Supabase и закрывает изолированную базу после выполнения.

Это не полный локальный Supabase и не проверка конкурентных транзакций на независимых соединениях. Серверные блокировки, уникальность и внешние ключи покрыты последовательными SQL-сценариями и ревью; многосессионный тест не заявляется выполненным.

Браузерная QA на тестовых данных — отдельная локальная проверка реальных React-компонентов, не подтверждение работы продакшен-связок. Полный опубликованный сценарий Auth → заявка → код → связь с парой → результат → профиль выполняется отдельным этапом после согласования публикации.

## Публикация

Новая миграция: `supabase/migrations/20261030120000_player_match_history.sql`. Не применять массовый `supabase db push` без сверки существующей истории миграций. Сначала согласовать применение проверенного SQL, затем публикацию проверенной ветки через стандартный GitHub workflow. Без миграции интерфейс корректно показывает ошибку загрузки, а не отсутствие результатов.
